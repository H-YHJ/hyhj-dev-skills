# UI 质量：按改动选择检查

这份参考用于页面、组件、主题、图片及交互变化。先看相关部分，不把全篇变成每次任务的验收负担。

## 信息与任务

- 从用户进入页面到完成主要操作走一遍，确认每个明显可点击元素的结果。
- 页面优先展示当前任务、必要信息和下一步；空状态给出可执行的开始方式。
- 多步配置说明当前位置、后续步骤和结果；不要为了形式把简单操作拆成向导。
- 工作台的导航、筛选、主体和详情保持层级；看板先帮助判断趋势或异常，再提供明细。
- 沿用产品的文字语言与密度，避免在正常流程堆放实现术语或功能宣传。
- 重要状态同时使用文字、图标或结构表达，不只靠颜色或 Tooltip。
- 长文本、缺字段、极端值和空值仍需保持可读；不要靠截断隐藏关键区别。

## 组件与完整状态

- 在现有组件中寻找已有的交互、尺寸和状态约定，复用可访问性原语与语义元素。
- 统一同类操作的命名、图标、位置和反馈；新组件确有差异时说明其责任。
- 只为真实场景定义状态，不要求每个元素都拥有同一套枚举。
- 请求进行中保留上下文，防止不合理重复提交；允许取消时清楚说明取消的效果。
- 空数据说明如何开始；失败说明可做的恢复动作，必要的详情可追踪而不泄露私有信息。
- 重试应保留合理输入，并防止重复创建、下载或写入。
- 保存、草稿、预览、应用和发布如有区别，需要在交互与反馈中保持一致。
- 页面显示“成功”前确认关键操作真正完成；乐观更新失败时有清楚的恢复路径。

## 响应式与滚动

- 沿项目已有布局和断点适配内容，不为通过一个截图宽度堆叠补丁。
- 根据受影响组件选择窄屏、常见手机、平板、桌面或横屏检查；不规定通用固定尺寸。
- 检查导航、长标题、按钮组、表格、图片和弹层在真实内容下的换行与溢出。
- 确认页面、面板和弹层的滚动归属，避免双滚动、滚动锁残留或关键操作被裁切。
- 表格确需横向滚动时给出可理解的容器和操作方式，不把所有宽内容强塞到屏内。
- 覆盖虚拟键盘、浏览器工具条变化或安全区中与本次功能有关的影响。
- 小屏调整信息顺序与布局，保证用户仍可完成主要任务。

## 图片与连续操作

- 原图保留；公开副本按用途压缩与生成响应式尺寸，避免不必要的元数据随图公开。
- 明确需要裁切还是完整查看，保留主体、长截图和文档的可读性。
- 图片加载前的布局由稳定容器控制，不依赖加载后的固有尺寸撑开页面。
- 处理加载、失败与合理重试；来源改变后重置与该来源关联的状态。
- 快速切换图片、分类或页面时，防止旧请求结果覆盖新选择，或让旧图冒充新图加载成功。
- 多图界面按需要延迟加载或分组，避免手机为小缩略图下载全部原图。
- 放大预览保留关闭、切换、标题和当前位置，适配高度变化与安全区。
- 关闭预览后恢复合理焦点和滚动位置；不要丢失用户当前浏览上下文。

## 键盘、焦点与触摸

- 控件使用符合用途的元素与可访问名称；图标按钮也必须说明动作。
- 焦点顺序跟随操作逻辑，焦点样式可见；不要只测试鼠标悬停。
- 菜单、弹窗、抽屉与对话框沿用成熟原语；检查进入、关闭和焦点回到触发处。
- 需要模态行为时限制背景操作；关闭后恢复滚动与键盘访问。
- Escape、方向键、确认键等行为符合控件语义，不无条件覆盖浏览器或输入法操作。
- 触摸目标、间距和反馈按项目规范及设备使用情境判断，不用一个固定值替代实际可用性。
- 拖拽有与任务相称的非拖拽操作方式；拖动中及结束后结果清楚。
- 关键文字和操作不能只靠 hover 出现；触摸与键盘有等价访问路径。

## 动效

- 先说明动效解决什么问题：状态反馈、空间连续性、注意引导或操作结果。
- 用户输入应立即得到反馈；转场不要锁死操作或掩盖真实等待。
- 快速连续操作时动画可合理中断或切换，避免队列累积和旧状态闪回。
- 优先选择易于保持流畅的属性和实现；大面积模糊、阴影或持续动效需评估设备代价。
- 跟随系统减少动态效果偏好，必要时取消位移或连续运动，同时保留状态含义。
- 不为追求某种平台风格加入无意义弹跳、延迟或透明材质。
- 涉及滚动、拖拽或连续切换时实际操作；静态截图无法证明动作质量。

## 主题与内容保真

- 产品背景、文字、边界、状态、控件和过渡状态使用项目语义 token。
- 同时检查加载、空白、失败、选中、禁用和焦点，不能只检查理想静态画面。
- 文档纸张、幻灯片、原始 HTML、地图、媒体或代码编辑器可能拥有独立配色。
- 例外限制到实际内容画布，不让外围工具栏、标签、加载、错误或滚动容器继承例外。
- 使用项目已有标记方式记录例外与原因；不要强制引入新的 DOM 属性命名。
- 第三方内容无法重着色时，保持边界与周围控件清楚，并验证产品主题切换。
- 颜色、图形与文字共同表达状态；主题改变后仍需区分差异、警告和当前选择。

## 素材与公开内容

- 事实、数字、身份、成果和图片说明应有来源；不清楚时不猜测。
- 用公开允许的摘要或改写稿，不把原知识库、简历、内部文件和草稿直接打入产物。
- 图片、联系方式或第三方信息沿用已确认的公开范围；新增范围才需要确认。
- 页面与可下载资源都属于公开检查范围；仅从界面隐藏并不能保护私有文件。
- 使用生成图片或替代素材时明确其用途，不能伪造真实成果或产品截图。
