# 验证与交付：以实际覆盖为准

用能够判断此次变化是否正确的证据收尾。风险决定深度，测试数量、固定流程和截图数量不代表质量。

## 选择最低充分证据

| 变化 | 优先证据 | 按影响补充 |
| --- | --- | --- |
| 小范围文案、间距或颜色 | 打开受影响页面，检查内容与相关视口 | 主题、长文案或布局边界 |
| 组件或表单交互 | 操作主要路径、失败与恢复 | 键盘、触摸、焦点及针对性测试 |
| 共享逻辑或状态 | 现有单元测试与契约验证 | 关键调用方、竞态和边界输入 |
| 请求、保存或认证 | 真实集成路径及持久化结果 | 拒绝访问、重试、刷新或重新登录 |
| 图片、预览或动效 | 实际加载与连续操作 | 慢速、失败、来源变化、横竖屏与减少动态效果 |
| 依赖或构建配置 | 对应安装与生产构建检查 | 路由直达、资源路径及目标运行环境 |

先采用项目现有命令和工具。没有对应命令时，使用可审查的原生检查、最小脚本或手动操作；不要假装执行了不存在的测试。

## 开始验证前

- 明确本次触及哪些页面、组件、状态和数据，防止只测入口却遗漏实际调用方。
- 检查环境、服务与登录状态，区分真实服务、受控测试替身和明确标记的演示数据。
- 测试替身可用于隔离逻辑，但不能证明真实后端、权限或持久化已接通。
- 优先使用隔离的测试数据或可恢复操作；不为验证而扩展到未授权的生产修改。
- 有现成基线先了解其状态，后续才能区分已有失败与本次回归。
- 本次不涉及的服务不必为形式启动；服务不可用时保留可执行的独立验证。

## 自动化反馈

- 新业务行为或已复现缺陷适合先建立失败反馈，再实现或修复。
- 使用能反映用户结果或契约的断言，避免只复述当前实现结构。
- 小范围 CSS、文字或可逆细节不机械要求 TDD，不建立只匹配文案或类名的脆弱测试。
- 共享状态、解析、保存、缓存、认证或连续请求变化，优先覆盖真实边界和调用关系。
- 涉及异步行为时，覆盖与本次改动有关的乱序返回、取消、重复操作或卸载场景。
- 依赖声明、类型或公共组件变化，运行相应类型检查或构建，不能只凭开发页面能打开。
- 必要检查通过后继续交付；只有新改动、失败或未解决疑虑才需要重复、扩大检查。

## 浏览器检查

页面呈现、DOM 交互或路由集成变化时，按受影响功能选取场景。已有测试直接覆盖纯逻辑修复时，按剩余集成风险决定是否补充页面检查，不为形式强行打开页面或穷举整个产品：

1. 进入真正使用该能力的页面，执行主操作并确认结果。
2. 检查与本次变化有关的加载、空状态、失败及恢复。
3. 在相应视口查看长标题、按钮、图片、滚动和弹层。
4. 涉及交互时使用键盘和触摸等相应输入方式，关注关闭后的焦点与滚动恢复。
5. 涉及保存时刷新或重新进入，确认显示来自预期数据来源。
6. 查看相关控制台或网络错误，判断是否与本次路径有关。

能自行启动开发服务与打开预览时就完成，不把本可执行的步骤交给用户。浏览器工具不可用时先完成其他有效检查，说明未进行真实 UI 操作，并给出可复验的入口与步骤。

## 视觉比较

- 对齐参考与实现的页面、视口、主题、内容和动画阶段，避免把采样差异当成布局问题。
- 先检查布局与信息层级，再检查字体、间距、色彩、图片和控件细节。
- 桌面布局接近参考不能替代手机适配；小屏以完成同一任务为目标。
- 截图比较适合定位视觉差异，实际点击、输入与连续操作用于判断行为。
- 使用真实数据样例或受控夹具，说明哪些状态没有出现，不能据此宣称它们已验证。
- 不为掩盖回归直接更新视觉基线；先检查差异原因并作出有依据的决定。
- 截图不包含凭据、私有资料或不必要的个人信息。

## 数据、权限与发布边界

- 需要保存的数据，确认写入成功与重新读取，而不只看前端提示。
- 按相关需求检查匿名、无权限、过期或退出状态；不为纯展示调整强制建立认证系统。
- 公开包检查实际文件与资源路径，不能只凭界面不可见判断未泄露。
- 本地预览、演示数据、测试通过、部署成功与正式上线属于不同证据。
- 若任务已含发布授权，沿用其范围完成并检查正式网址、资源和页面直达。
- 若任务未授权发布，交付可审查版本；只为真正缺失的外部动作授权询问一次。
- 维护旧内容或验证写入时，恢复自己产生的测试数据，保留用户已有更改。

## 失败与能力不足

- 记录具体失败命令或操作、可观察现象，以及阻塞的是哪一项验收。
- 优先判断环境问题、已有缺陷与本次回归，不凭猜测宣布唯一原因。
- 能在现有授权与项目环境中修复的依赖或配置问题继续处理，并重跑受影响检查。
- 缺凭据、访问权限或外部服务时，不静默切换到本地替代后声称集成完成。
- 使用替代检查时说明它覆盖什么、无法覆盖什么；未知结果保持未知。
- 未验证的平台、设备或系统偏好明确列出，模拟视口不能称为真机测试。

## 交付可以这样表达

简洁说明结果、证据和缺口，不需要按固定模板逐条罗列：

> 已完成页面的筛选与详情跳转，并保持刷新后的筛选条件。相关构建与集成检查通过；已在桌面和模拟手机视口操作主路径、空结果和失败重试。尚未在实体手机验证。

涉及持久化时说明实际数据来源；涉及预览或发布时给可查看入口。若仍需决定，给出具体事项与影响；没有缺口就直接完成交付。
