# 技术栈适配

识别或修改 Python/FastAPI、Java 后端，或工具条件与原计划不一致时读取。这些是适配线索，不是迁移指令；其他语言沿用相同契约、数据和验证原则。

## 先识别项目，再选择实现

查看实际构建清单、锁文件、运行入口、迁移工具和相关代码的惯用方式。
说明文档与依赖版本不一致时，以实际清单判断安装状态，以有效决策判断计划目标。

- 既有项目延续现有语言、框架、测试栈和部署方式。
- 不为使用熟悉工具而改写服务，不自动升级框架或运行时。
- 新项目没有技术选择时，先依据业务规模、团队经验、部署条件和依赖生态提出建议。
- 选择新库前评估维护状态、兼容性、许可证与引入成本，遵循项目已有依赖策略。
- 涉及可能变化的版本、API 或安全支持信息时，使用可用的官方资料核验。
- 精确版本由项目清单和运行条件决定，不把本 skill 的例子写成固定版本要求。

## Python / FastAPI 参考

适用于项目已经采用 Python，且以下工具实际存在或确有引入理由的情况。

| 现有能力 | 适配重点 |
|---|---|
| FastAPI 或类似框架 | 路由和依赖注入处理协议边界；业务服务承载用例 |
| Pydantic 或类似校验库 | 区分输入、输出与内部模型，核对缺省、空值和序列化 |
| SQLAlchemy 或其他 ORM | 会话生命周期、事务边界、关系加载与数据库约束 |
| Alembic 或其他迁移工具 | 模型变更对应版本化迁移，检查生成脚本的真实影响 |
| 异步驱动 | 避免阻塞事件循环，处理取消和连接回收 |
| 已有测试与静态工具 | 运行相关检查，不为了统一工具而更换整套链路 |

### 请求与任务的资源生命周期

- 数据库会话按既有工作单元管理，不跨不相关并发任务共享可变会话。
- 依赖注入的清理行为、事务提交点与异常传播需保持一致。
- 后台任务不继续使用已经结束的请求上下文、临时句柄或会话。
- 同步 I/O、CPU 密集处理和异步 I/O 按实际负载安排，不机械增加 `async`。
- 消费端取消时正确释放资源；不能捕获取消后继续当作正常成功。
- 生成式响应结束时机不同于普通响应，要核对数据写入和资源关闭时序。

### Schema 与 ORM 的边界

外部响应应只包含明确允许的字段，避免直接暴露完整持久化对象。
序列化时发生隐式加载可能带来查询风暴或会话关闭错误，应按真实调用链验证。
对批量读取关注实际查询次数和规模，不因一个列表就预建缓存或搜索服务。
自动生成迁移是草稿，需要检查删除、重命名、约束及索引行为。

## Java 参考

当项目采用 Java 时延续现有框架、构建工具、ORM 和测试组织，不要求改成 Python。

- 运行时版本依据项目支持矩阵、依赖兼容和部署环境确定；升级单独评估。
- 已有分层清晰时维持边界；协议入口、应用编排、业务规则和外部适配职责分开。
- 核对事务代理、传播与异步边界，避免以为注解存在就已获得预期事务。
- 线程池和队列有明确容量、拒绝行为和清理方式；核心任务不依赖不可控并发。
- 共享状态优先使用不可变值或受控并发结构，长耗时调用不无故持锁。
- `equals` 与 `hashCode`、空值、包装类型比较及集合所有权按实际用法核对。
- 时间使用项目约定的现代时间类型，明确跨系统时区；金额使用十进制或最小单位整数。
- 依赖版本管理沿用构建平台，不因单次需求引入第二套版本规则。
- 集成测试可用项目已有容器或隔离服务，工具不是完成条件，行为证据才是。

不机械照搬旧手册中的固定容量、表行数、关联数量、字段前缀或全局禁止规则。
根据查询计划、负载、数据库能力和维护成本决定，而非用经验数字代替验证。

## 与调用方协作

后端定义并实现有效契约，调用方负责已声明的交互和渲染职责。
字段、错误、流式事件或状态语义发生变化时，明确双方需要同步的内容。
不能用前端缓存覆盖业务事实，也不能未经需求确认将所有临时交互状态强制持久化。
接口尚未实现时，可以使用标明用途的替身开展隔离开发；最终集成状态单独验证。

## 工具或环境不可用

优先使用仓库已有命令、标准库和现有接口完成工作。
专用工具、外部 skill 或插件缺失时，判断是否有等价的原生方式，不先要求安装。
需要选择外部技能时，再读 [技能选择](skill-selection.md)。
没有真实数据库或第三方沙箱时，仍可完成代码、契约与隔离测试，标明集成验证缺口。
工具缺失不能成为伪造通过、跳过权限或改用生产资源的理由。
任务未要求安装、发布或调整环境时，不自动修改全局配置或引入新服务。
