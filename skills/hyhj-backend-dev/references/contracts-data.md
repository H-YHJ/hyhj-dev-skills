# 契约与数据

接口、权限、数据模型、事务、迁移或文件处理发生变化时读取。沿用项目现有协议与一致性要求，不借局部修改统一改造全部接口。

## 接口契约与兼容

先从实际注册路由、类型/Schema、调用方和现有测试确认外部契约。
OpenAPI 能帮助比较声明；认证、权限、错误、副作用和流式行为还需行为证据。

- 保留契约时，核对方法、路径、参数位置、字段、默认值、空值、状态码和认证语义。
- 只在用户要求或已有有效决定下做不兼容调整，同时处理受影响调用方。
- 新接口延续项目响应、错误、命名和分页约定；不自动切换统一响应封装或路径前缀。
- 没有约定时，选择清楚且适合调用方的形式，并说明决定，不建立全项目改造任务。
- 区分字段缺省与显式清空，避免部分更新意外覆盖存量值。
- 时间说明时区和单位；金额说明币种、精度及舍入，避免浮点误差影响业务结果。
- 列表限制单次成本，并采用稳定排序；分页方式依据数据规模和访问模式选择。
- 业务状态与 HTTP/传输成功分开；接收请求不表示业务已完成。

既有接口重构宜保存可比较的契约基线，并验证变化是否落在授权范围内。
静态 Schema 相同仍可能破坏默认值、排序、权限或重复请求语义。

## 身份、资源权限与输入

身份认证回答“谁在调用”，资源授权回答“能否操作这个对象”。两者分别核验。

- 由可信服务端身份获取权限上下文，不能仅相信请求里的用户或租户标识。
- 对读取、修改、下载和任务查询分别校验资源权限，避免只保护列表入口。
- 校验外部输入的类型、范围、长度及业务含义；数据库查询使用参数化语句。
- 请求中的资源 ID 需要验证归属与可访问性；不能因猜不到 ID 而省略授权。
- 上传、远程抓取和回调按实际威胁检查大小、类型、目标地址与访问边界。
- 对外错误不泄露凭据、堆栈或内部路径；保留可供追踪的错误标识。
- 日常操作沿用既有授权；权限规则、数据可见性或对外副作用发生变化时确认需求。

## 权威数据与模块所有权

先回答每项数据由谁创建、更新、读取、删除，谁能决定它的最终状态。
数据库、对象存储、缓存和搜索索引的职责取决于当前架构，不按产品名称预设。

- 业务记录与派生索引区分；说明索引延迟、重建来源及查询时的权限依据。
- 同一状态不由多个入口各自维护，协议适配应调用同一业务用例。
- 跨模块访问遵循现有公共接口和事务边界，避免新添隐式耦合。
- 缓存失效或重建失败不能被解释为权威数据已删除。
- 客户端临时状态可以服务交互，已提交业务事实以已声明的服务端权威为准。
- 跨模块隔离、跨表约束和查询方式依项目需要选择，不一律禁用外键或关联查询。

## 事务、并发与幂等

先识别不可破坏的业务约束，再选择数据库约束、事务、版本校验或锁。

- 唯一性等关键不变量优先由合适的数据库约束兜底，应用校验提供明确反馈。
- 对竞争写入明确冲突处理，避免“先查再写”在并发下失效。
- 事务尽量只涵盖必要的本地操作；长耗时外部调用不无故占用锁或连接。
- 同一操作重复提交时，说明去重范围、请求参数冲突和结果读取方式。
- 有幂等键不等于所有操作都可安全重放，尤其需要检查外部系统实际副作用。
- 多存储写入无法原子完成时，选择暂存、补偿、对账或重建等适合当前规模的办法。
- 只有存在可靠异步发布需求时才考虑事务消息/Outbox，不为目录完整而引入。
- 金额、库存、权限、状态切换等核心约束要验证冲突和失败路径。

## 数据结构演进

采用项目已有的版本化迁移方式，避免仅修改 ORM 就宣称数据库已更新。

- 评估存量数据、锁表时间、索引构建、约束收紧以及新旧代码兼容。
- 需要数据转换时，说明范围、批次、重复执行安全性、失败位置和核对方法。
- 有正式历史数据时不得从某个开发项目推导“无需迁移，直接清空”。
- 发布顺序取决于兼容窗口，必要时分为扩展、切换、收缩，而非一次破坏性修改。
- 备份与恢复方式应覆盖变更影响；不可逆变更提供前向修复方案并说明边界。
- 在可用隔离环境执行或检查迁移，报告实际验证的数据库与版本范围。

## 文件与制品生命周期

文件身份、对象内容、业务用途关系和处理结果应有可解释的所有者。

- 下载通过受控标识、权限与有限有效期地址，避免永久公开敏感对象。
- 文件名和客户端路径不能直接变成服务端存储路径或命令参数。
- 先存对象还是先记元数据依据一致性方案选择，处理任一步失败后的残留。
- 解析、预览、索引与生成制品记录来源和状态，失败不能冒充处理完成。
- 删除时考虑任务、引用、派生内容和对象清理；保留审计按项目政策执行。
- 清理需要可重试且避免误删仍被引用的内容，不默认承诺立即物理删除。

## 验证落点

对本次变化形成一条证据链：请求与身份 → 业务决定 → 写入或副作用 → 独立读取结果。
结合风险选择权限失败、重复提交、并发冲突、部分失败或迁移前后兼容用例。
真实存储不可用时报告未验证；替身测试只证明其明确覆盖的逻辑。
